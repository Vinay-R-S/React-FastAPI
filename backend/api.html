Feedback System API

Simple feedback collection API. This README contains the development base URL, endpoints, request/response examples, and notes for authentication and roles.

Base URL (development):
http://127.0.0.1:8000

Authentication

This API uses JWT tokens. Signup and login return an access_token which must be sent as Authorization: Bearer <token> for protected endpoints.

POST /signup

Create a user account.

Field Type Notes
email string Unique email
password string Plain text (server will hash)
name string Display name
is_admin boolean Set to true for admin users (use carefully)
Request body 
{
  "email": "alice@example.com",
  "password": "supersecret",
  "name": "Alice",
  "is_admin": false
}
Response (200) 
{
  "message": "Signup successful!",
  "access_token": "<jwt>",
  "token_type": "bearer",
  "user": { "id": 1, "name": "Alice", "email": "alice@example.com", "is_admin": false }
}

POST /login

Authenticate and receive a JWT token.

{
  "email": "alice@example.com",
  "password": "supersecret"
}

Note: Keep the access_token safe. Use it in the header: Authorization: Bearer <access_token>

Products

Products endpoints let you list and (admin) manage products.

GET /products

List products. Query params:

Query Description
search Search by product name or description
sort_by Field to sort by (default: created_at)
order asc or desc (default: desc)
Response 
{
  "data": [
    { "id": 1, "name": "Product A", "description": "...", "price": "400" }
  ]
}

POST /products Admin

Create a product. Requires Authorization header with admin token.

{
  "name": "New product",
  "description": "Short description",
  "price": "123"
}

PUT /products/{product_id} Admin

Update product fields (partial updates allowed).

DELETE /products/{product_id} Admin

Delete an existing product.

Reviews

Reviews are attached to products. Authenticated users can CRUD their own reviews; admins can delete any review.

GET /products/{product_id}/reviews

List reviews for a product. Supports query params:

Query Description
min_rating Minimum rating filter
max_rating Maximum rating filter
sort_by Field like created_at or support_count
order asc or desc
Response 
{
  "data": [
    {
      "id": 1,
      "product_id": 2,
      "user_id": 3,
      "name": "Bob",
      "rating": 5,
      "review": "Great!",
      "support_count": 10,
      "created_at": "2025-10-01T12:34:56Z"
    }
  ]
}

POST /products/{product_id}/reviews Auth

Add a review for a product. Requires Authorization header.

{
  "name": "Bob",
  "email": "bob@example.com",
  "phone_number": "1234567890",
  "rating": 5,
  "review": "Loved it"
}

PUT /reviews/{review_id} Owner

Update your review (owner-only). Provide changed fields in the body.

DELETE /reviews/{review_id} Owner

Delete your review (owner-only).

DELETE /admin/reviews/{review_id} Admin

Admin may delete any review.

Database Schema (summary)

Simple summary of essential tables:

Table Important Columns
users id, name, email, password_hash, is_admin, created_at
products id, name, description, price, created_at, updated_at
reviews id, user_id (FK), product_id (FK), name, email, phone_number, rating, review, support_count, created_at, updated_at

Common Requests (cURL)

Login (cURL) 
curl -X POST http://127.0.0.1:8000/login \
  -H "Content-Type: application/json" \
  -d '{"email":"alice@example.com","password":"supersecret"}'
List products (with search & sort) 
curl "http://127.0.0.1:8000/products?search=widget&sort_by=name&order=asc"
Create product (admin) 
curl -X POST http://127.0.0.1:8000/products \
  -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"name":"New product","description":"desc","price":"199"}'
Post a review (auth) 
curl -X POST http://127.0.0.1:8000/products/2/reviews \
  -H "Authorization: Bearer <USER_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"name":"Bob","email":"bob@example.com","phone_number":"1234567890","rating":5,"review":"Loved it"}'

Tips & Notes

  • JWT tokens must be included for any endpoints marked Auth or Admin.
  • Admins should limit usage of admin endpoints — consider protecting them further by IP or additional checks in production.
  • Support counts are integers and can be used to sort/popularize reviews.
  • Pagination: endpoints that return lists should include pagination parameters (page, per_page) in production. Add them to the query when you implement client-side pagination.

Response Conventions

Standard success wrapper:

{
  "message": "Human readable message",
  "data": { ... }   // when applicable
}

Error Handling

Errors use standard HTTP status codes and return JSON:

{
  "detail": "Error message or reason"
}
